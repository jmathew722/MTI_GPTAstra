## Decisions made without explicit guidance
- A flat folder now means "each file is one part" (previously a flat folder of images was one multi-view part). A subfolder of view images is still one
  multi-view part. This follows the requirement text; recorded here because it changes the old behaviour of a flat image folder.
- The rubric version is a fingerprint of `bench/score_config.yaml` (the scorer has no version number of its own).
- `scoring.md` was supplied as an attachment, not as a file in the repo. The methodology panel reads the live scorer config and mirrors the
  formulas of `scoring.md` part B; a test cross-checks them against the scorer's own modules.
- The legacy "Scoring Rubric" section in Pipeline Results no longer reads `scores.json` itself. It shows the stored evaluation from the Scoring
  tab and links there; the advisory MTI practices checklist stays.
- Estimates use the 25th to 75th percentile of finished runs (min to max with fewer than 3 runs, flagged "limited history"). A batch is the sum of its
  parts because SolidWorks automation is serialized.

## Addendum 2: colour coding and the empty Build Plan (same day)

**Why the Build Plan was empty for every build.** The Build Plan section only understood the legacy v1 plan, which has a top-level `steps` array.
Every current build goes through the Feature-IR path, whose `plan.json` is `{dims, reference_ids, plan: {ir_version, frame, features[], notes}}` with **no
`steps` array**. The viewer found no steps and printed "No steps array found", so the tab looked empty for all builds. A second, related miss: the run
list's presence check looked only for `*_build_plan.json`, so the Projects "Plan" badge was also off for every IR build.

**Fix.** `logic/planview.js` reads both shapes. For an IR plan the tab now shows: facts (part, units, plan format, origin, "N of M built", dimensions),
colour-coded status counts, every operation in build order with a coloured kind chip (extrude blue, cut orange, hole and pattern violet, edge treatment
amber) and the status SolidWorks reported for it (`ir_report.sw_features`: Built green, fallback amber, needs a decision orange, skipped or failed red),
the plan's numbers resolved from the dimension table (`D010 / 2 - D009 = 1.2505`, by a small arithmetic parser, never eval), the drawing callouts, flags
and defaults attached to the operation, a dimensions table (used-by counts, "unused" and "reference only" notes) and the planner's notes. Search and the
Raw toggle still work; a legacy v1 plan still renders its steps. The server now sends `sw_features`, `flagged`, `defaults` and related fields in the
`ir_report` category, and counts `plan.json` as a build plan in the run list.

**Colour coding.** One tone vocabulary (green, amber, orange, red, blue, violet) with a word and glyph wherever it is a verdict.
- Pipeline Results: every section has a health tone from its real content (`logic/resulttone.js`): build plan (all built / not built / fallback / open questions), verification and model check, engineering flags (worst severity), recording status, must-meet fails, cost pricing, Files, Console (errors/warnings). The tone colours the navigation dot, the section's status chip (with its word, e.g. "all built", "2 errors") and an accent bar on the section. Chips gained blue, violet and orange tones; unpriced cost is orange; files get a dot per type.
- Scoring: row accents and tints by band, item rows tinted by credit band, issue codes coloured by severity, six category accent colours (non-band hues, so a category never reads as a verdict) on the cards and a proportional weight bar in the methodology, through/blind/counterbore chips in the holes table, band pills in the history, band-coloured example rows.

Tests: `planview` 8 and `resulttone` 6 unit tests (including a test over the real A040501E plan: 10 operations, all built); 5 browser tests in
`26-v4-color-and-build-plan.spec.ts` (IR build tab, search/raw/legacy v1, run list Plan badge, navigation tones, Files and Scoring colours) with axe clean.

Regression after this change: UI server 95 passed; UI unit 218 passed + the 3 old missing-fixture failures; full Playwright suite **58 passed, 14 failed, 6 skipped** (the same 14 that fail on the clean v3 code). The pipeline repo was not touched in this change.

## Addendum 3: standardized grading spectrum (same day)

Every 0-100 score in the UI now takes its colour, word and glyph from ONE utility, `web/static/js/logic/grade.js` (`McA.grade`), mirrored by `--grade-*` tokens in
`design-tokens.css` (a unit test keeps them identical). Fixed thresholds on the ACTUAL number, for every number, bar, badge, chart and table cell:

| Score | Grade | HEX |
|---|---|---|
| 0-39 | Poor | `#D95763` |
| 40-59 | Below Average | `#D98B55` |
| 60-79 | Fair | `#D6AF6B` |
| 80-89 | Good | `#B5C76B` |
| 90-99 | Excellent | `#8DD49A` |
| 100 | Perfect | `#4CB782` |

- A smooth gradient (`grade-spectrum`) is used only for spectrum visualisations (the legend bar with an average marker); individual numbers use the fixed colour.
- No rounding up: 99.99 is Excellent (never Perfect) and is shown as 99.9; formatting truncates, so only exactly 100 reads 100.
- Missing, unavailable or invalid scores (null, NaN, below 0, above 100, Incomplete, no part, scoring failed, pending) are neutral grey `#92949E`, never red.
- Applied to: Scoring (overview stats and distribution, legend, results table, score ring, category cards and strip, item credits, history, methodology, worked example), Projects (card badge and a Score column in the runs table), the Workspace header (new "Fidelity score" chip for the selected part), Pipeline Results (the fidelity section and the graded macro readiness, geometry, dimension, consistency and feature-confidence figures, reported by the pipeline as 0..1 fractions).
- The scoring methodology, calculations and weights are untouched; the engine's own band ids are ignored by the UI (a test proves a server band is overridden by the actual score).
- Accessibility: every grade colour is at least 4.5:1 on the card surface (a unit test checks it). `#D95763` is only 4.51:1, so the Poor grade has no fill behind it (border, text and glyph only); the neutral grey is the palette's muted ink, 5.6:1.

Found while testing: a burst of PDF previews and page counts can crash the server, because MuPDF is not thread-safe and FastAPI runs sync endpoints on a thread pool. The server died twice in the browser tests
with a "MuPDF error" line and stayed up with the fix. Every server-side PyMuPDF call now holds one lock (`estimates.FITZ_LOCK`); a 16-thread regression test covers it.

Tests: `grade.test.js` 11 (all boundaries 0, 39, 39.99, 40, 59.99, 60, 79.99, 80, 89.99, 90, 99.99, 99.999, 100; invalid values; formatting; spectrum; contrast; token mirror), `scoringview.test.js` 10,
browser `27-v4-grade-spectrum.spec.ts` 7 (exact HEX in the real UI at every boundary, un-rounded display, grey for missing, legend, Projects/Workspace/Results, distribution, narrow layout; axe clean).

Regression after the grading spectrum: UI server 96 passed; UI unit 228 passed + the 3 old missing-fixture failures; full Playwright suite **65 passed, 14 failed, 6 skipped**. 13 of the 14 are the known baseline failures; the 14th alternates between two racy older tests (`22-stage3-flags` keyboard and `23-engineering-markup` test 44, which swallows a seeding error with `.catch(() => '')` and then asserts the session): test 44 passes about one run in three on its own and is unrelated to this change.

## Addendum 4: always-fresh UI, coloured numbers everywhere, action buttons that pop

**"The scores are not colour coded".** The colours were in the code and in every browser test, so the likely cause is a browser keeping an OLD cached stylesheet or script: the server sent the UI files with no cache policy,
and browsers keep such files for a while without asking again, so new scripts could run next to an old `pages.css`/`design-tokens.css` with no grade colours. Fixed so it cannot recur:
`index.html` is now served with every `/static/...` URL stamped `?v=<fingerprint of all UI files>` (a changed file is a new URL), and `/`, `/static/*`, `/photoapp/*`, `bridge.js` and `pdf.min.js` are sent with
`Cache-Control: no-cache` (always revalidated with an ETag, answered 304 when unchanged). A server test and a browser test check both. After updating, one hard refresh (Ctrl+F5) clears any copy cached before this fix.

**More numbers coloured.** Every number on the Scoring overview now takes a grade colour: Parts scored (by the share of parts scored), Average fidelity, Need attention (by the share that is not weak), Not scored (neutral grey, or Perfect when nothing is waiting);
the worked-example scores and per-category cells, the credit-curve values in the methodology, the attention list scores, the results-table scores. Missing values stay neutral grey.

**Buttons that pop.** Open, Open in Workspace, Results, Details, Evaluate, Re-evaluate and Evaluate all are larger (38 px, was about 30) with weight 600 and a small lift on hover, in the theme families:
Open is solid violet like Save part, Details is violet-tinted with a violet border, Results and Evaluate/Re-evaluate are champagne-gold tinted with a gold border (quieter than the solid gold Run Pipeline, so Run Pipeline stays the one gold call to action).

Two accessibility defects found by the new axe checks on Projects were fixed: the "file not present" chips were 3.4:1 (now readable with a dashed outline), and the unavailable-preview button's accessible name now contains its visible text.

Tests: server `test_the_ui_is_never_served_stale`; browser `28-v4-buttons-and-number-colour.spec.ts` 4 (overview, example and credit-curve numbers all grade-coloured; results-table buttons at least 38 px, violet and gold borders, hover lift; Projects Open is `rgb(155,138,251)`;
versioned and revalidated assets); axe clean on Scoring and Projects.

Regression after this change: UI server 97 passed; UI unit 229 passed + the 3 old missing-fixture failures; full Playwright suite 68 passed, 15 failed, 6 skipped: the 13 known baseline failures, plus the two racy older tests noted above (`22-stage3-flags` keyboard), and one of this suite's own tests that read the Projects order before the cards had rendered (fixed: it now waits for the cards, and passes 3 of 3 reruns).

## Addendum 5: layout and visual-consistency audit (accent lines vs text)

**Defect.** On Pipeline Results (Engineering Flags and every other section) the coloured health bar overlapped the section heading and body text. Root cause: `.rsec` drew its bar as `box-shadow: inset 3px 0 0 <tone>` but had no padding, so the bar sat at x=0-3px, exactly where the text starts (measured gap -3px). Fixed at the cause, not hidden: `.rsec` now has `padding-left: var(--sp-4)` (content sits 13px clear of the bar, above the 8px minimum) and the same radius as its bar.

**Same audit, other findings fixed.** `.res-link` (Results navigation, selected item) had only 5px between its 2px accent and its label; padding raised to 12px (10px clear). The Workspace 3D/2D viewer header was `nowrap`, so with the inspector open the status badge shrank to "Gene..."; the header now wraps and badges never shrink (`.vp-head .badge-c {flex:none}`).

**Audit tool (kept as a regression test).** `tests/e2e/helpers/layout-audit.ts` measures, for every element with a left border of 2px or more or an inset side bar, the gap from the accent to the left-most text, icon, control or table inside it (minimum 8px), and also flags text clipped by `overflow:hidden`, status labels/chips/buttons/tabs that are ellipsized, and any sideways page scroll. `29-v4-layout-audit.spec.ts` (3 tests) crawls Home, Projects, Scoring (every tab and the detail view), Recent, Help, Settings, every Pipeline Results section, and the Workspace with its Results drawer, at 1920x1080, 1440x900, 1366x768, 1100x800, 800x900 and 390x844 (these widths also stand in for 125-300% browser zoom) with the sidebar expanded and collapsed. Negative control: with the old `results.css` the Results test fails; with the fix all three pass.

Already compliant and left alone: flag cards and issue rows (4px border, 12px padding), build-plan operations, attention items, category cards (16px), warning notes (8px after a 3px bar). Severity colours stay on their own cards; the section bar only spans its own section.

Screenshots: `docs/verification/v4/layout/` (Engineering Flags at 1440 and 390 wide, Results, Scoring part results and detail, Workspace). Unit tests unchanged (229 pass, the 3 known fixture failures).
