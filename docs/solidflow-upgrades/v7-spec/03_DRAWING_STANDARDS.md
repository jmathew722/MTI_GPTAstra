# SolidWorks native drawing presentation and layout

## Required drawing style
- Isometric view on every applicable drawing: **Shaded With Edges**, not wireframe or plain shaded. Use native view display mode, verify actual export. Orthographic/section/detail views retain standard line conventions, usually hidden lines removed unless needed. Isometric may use model shading; all dimension text, leaders, notes and linework remain black where applicable. White sheet, professional template, preserve reference sheet/projection when provided. Standard mode uses existing template and configured ASME/ISO rules; do not assert formal compliance without review.
- For applicable leadered notes and callouts set native **Custom Text → Broken Leaders, Horizontal Text** (verify actual SolidWorks 2025 UI/API mapping; not all annotation classes support identical options). Keep text horizontal and broken leader convention, appropriate arrowheads and attachment. Do not confuse this with manually overriding measured dimension values. For unsupported classes preserve correct engineering representation and report limitation. Use template drafting settings or annotation-specific native API; do not fake leaders with drawn lines. Validate in native document and PDF. Preserve source text semantics.
- Dimension all required geometry without duplicate controlling dimensions. Use hole/thread metadata only when supported by model/reference. Maintain appropriate diameters/radii, ordinate baselines, pattern quantities, center marks, section labels, notes. Never invent tolerance, material, finish or GD&T. Preserve source precision and units. Keep native references attached; no dangling dimensions or detached/fake numeric labels.

## Layout engine
Compute usable sheet polygon from actual sheet size, border, title block, tables, notes, and reserved margins. Treat views plus annotation envelopes as occupied regions. Position orthographic views aligned to projection conventions; reserve space for extensions and leaders; isometric typically in free upper/right region unless reference dictates otherwise. Use section/detail views only when needed; keep scales readable. View placement must be planned jointly, not independently.

Use native auto dimension/model-item import selectively, based on coverage ledger. Run native Auto Arrange Dimensions or corresponding supported API (e.g. installed AlignDimensions operation if semantically appropriate), per view/compatible groups; then inspect actual result. In reference mode use reference anchor locations as targets; auto-arrange must not unnecessarily destroy source layout. Capture pre/post dimension IDs, values, attachments and count; verify every required item remains present and visible. Do not blindly select all annotation types if API cannot handle mixed groups. Reposition individual annotations using native interfaces when necessary. Prefer deterministic collision-aware placement over manual mouse automation; fallback UI automation only if validated, isolated, and logged.

Collision detection: obtain native view outlines, text/annotation bounds or measured extents from exported PDF, leader/extension segments and occupied zones. Convert to a common sheet coordinate system. Detect text-text, text-geometry (except intentionally attached callout symbols), text-leader, text-border, text-title-block, overlapping views, clipped labels and illegible stacking. Exempt only documented standard intentional intersections (e.g. extension line meets dimension line, leader tip touches geometry, centerlines). Use configurable clearance (initial 1–2 mm sheet space) and dimension lane spacing based on actual font metrics. Check all sheets, including rotated/cropped exports. No blanket hiding, shrinking to illegible fonts, or removing dimensions to solve collisions.

Resolve by moving annotations into available lanes, staggering, flipping leader side, moving views while maintaining alignment, changing scale or sheet size with explicit deviation, or adding sheets if standard mode or approved reference-mode fallback. Rebuild and re-export after changes. In reference mode prioritize semantic completeness and readability over copying existing overlaps; explain relocation. If reference has collisions or too little room, flag the necessary layout deviation instead of falsely claiming identity. Preserve all required dimensions and text. Hard QA gate: zero unintended overlaps or clipping in accepted outputs, no lost required dimensions, no broken associations; if cannot achieve, mark review required and retain diagnostics.

## Validation
Reopen SLDDRW with valid model references and configuration; rebuild and check native style, attachment and view settings. Export every sheet to PDF; verify page count, visible text, shading, scale and no cropping. Save screenshots/full-sheet renders at sufficient resolution, native annotation inventory, collision reports, and evidence of corrections. Engineering review still needed for manufacturing release where design intent is absent.
