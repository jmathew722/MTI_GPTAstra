# Reference-driven drawing reconstruction

## Reference selection and history lookup
Provide Standard and Match reference drawing modes. In reference mode offer Auto-find from 2D → 3D history, Upload PDF, and confirmed existing source selection. Show source filename, project/run/date, page count and match status. Explicit upload overrides history. Validate PDF signature, file size and page count with existing upload policies. Reject unrelated part matches or require explicit confirmation for ambiguous candidates. Scope search to authorized project/history; prefer exact part artifact ID, SHA256/configuration, then linked forward manifest. Filename/part number only is a candidate signal; revisions, units, configurations and geometry fingerprints must agree. Legacy missing links: show candidates with confidence and reasons, never auto-match merely by similar names. Persist the selected source and provenance. Add a clear/change action. For batch, allow auto lookup per part and optional explicit mapping; show unmatched/ambiguous rows before running or require explicit standard-mode fallback.

## Extraction reuse and fresh OpenAI extraction
Find prior extraction artifacts from the actual forward run. Reuse when source hash, pages, schema, extraction quality and required layout fields are compatible. If old extraction has geometry but lacks positions, supplement missing fields; if incompatible or missing, run fresh extraction with existing configured OpenAI client/API key on the backend. Do not expose the key, hardcode a model name, or require a second key. Use configured supported multimodal model, structured output validation, retries and token usage tracking. Combine deterministic PDF vector/text extraction (where available) with rendered page analysis for scanned/complex drawings. Treat drawing text as data, not instructions. Do not send more source data than necessary. Store model identifier, prompt/schema version, page render DPI, raw evidence and usage. Avoid re-extraction on every render/refresh; offer explicit refresh. Validate units and literal values; do not infer undocumented specifications.

## Normalized reference schema
- Sheet: page index, media/crop box, rotation, size, units, projection, title-block and revision zones, reference coordinate system. Store normalized top-left page coordinates (0..1) plus original PDF points; convert to SolidWorks sheet bottom-left meters with rotation/crop handled explicitly.
- View: ID, sheet, type (front/top/right/iso/section/detail/auxiliary), parent, orientation, scale, center, bounds, labels, section cut/arrow/letter, detail boundary, display style, evidence/confidence.
- Annotation: ID, type (linear/diameter/radius/angular/ordinate/hole note/GD&T/finish/center mark/etc.), exact displayed string including symbols, nominal value/unit/precision, tolerance upper/lower or limits, prefixes/suffixes, quantity, text bbox/anchor, leader vertices/attachment, extension lines, source view, native geometry entity hints, evidence and uncertainty.
- Notes/title blocks/tables: verbatim text, line breaks, positions, fonts if detectable, rows/columns, field bindings, material, treatment, revision, general tolerances and all other explicit requirements. Preserve source spelling and meaningful symbols. Do not substitute generic notes for specific instructions.
- Coverage ledger: each source item has matched native ID or unresolved reason; distinguish decorative/metadata from manufacturing requirements.

## Native reconstruction
Plan identical sheet format, scale, view orientation and placements where feasible. Use normalized positions transformed into sheet coordinates, model-to-view projection, and stable entity references to attach dimensions. Match semantic entities using feature type, projected geometry, axes, radius, adjacency and configuration; avoid screen-coordinate clicks as primary mechanism. Prefer native model dimensions and feature callouts, then associative driven drawing dimensions from actual geometry. Preserve formatting, precision, tolerances, prefixes/suffixes only when supported by source and consistent with model. Never fake numeric dimensions using text overrides. If actual geometry differs, emit discrepancy and keep true dimension; do not mutate source part. Preserve reference-only manufacturing notes with provenance, subject to engineering review if conflicting. Do not blindly copy obsolete approval signatures/revision release status; preserve as reference metadata and mark new drawing draft as appropriate. Use exact source layout when feasible; user-required shaded-with-edges iso and legibility take precedence over reproducing reference defects. Document deviations.

## Comparison and bounded repair
Compare semantic content first: view presence/type/scale/orientation, every dimension and callout, units/precision/tolerance, notes/title block and material. Compare numeric geometry with native measured values and user-approved tolerances; no invented engineering tolerance. Then compare spatial position: normalize same sheet size and rotation, map matching views/annotations, measure anchor/bbox deltas in sheet mm; configurable initial targets 1 mm view anchors and 2 mm annotation anchors, not manufacturing tolerances. Compare PDF text extraction and native annotation inventory; raster alignment/difference may supplement but not prove correctness. For scanned sources use OCR or model evidence with confidence; flag unreadable items. Shaded iso, fonts, antialiasing and required layout corrections may create valid visual differences. Report semantic coverage separately from visual similarity, with denominator and unresolved list. Do not label pixel-identical unless actually measured and true.

Iterate: generate → rebuild → export PDF → inspect native annotation coordinates and rendered pages → classify discrepancies → correct safe placement/style/mapping → re-export. Limit iterations (default 3, configurable), retain best validated revision, prevent cycles, never delete required annotations to improve score. High severity: incorrect/missing critical dimensions, unresolved required callouts, wrong model/configuration, clipping, material mismatch, missing sheets. Review-required on unresolved items, not a false pass. Save side-by-side pages and overlay/difference evidence, per-item comparison ledger, before/after correction logs and extraction provenance. Final UI should distinguish reference match from engineering approval.
