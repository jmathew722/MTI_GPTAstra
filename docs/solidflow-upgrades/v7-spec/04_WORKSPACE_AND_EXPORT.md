# Workspace UI, reference viewer, and export

## Current layout and design intent
Screenshot shows reverse workspace: left source STL, right generated PDF, setup rail on far right, batch queue separated by large blank vertical region. Preserve existing Solid Flow charcoal, muted purple, gold and typography; reuse existing components. Setup side wording is inconsistent in request; preserve actual existing setup rail location (right in screenshot), place Export at bottom of setup rail. Avoid unrelated redesign.

## Setup rail compact layout
Use short labels, no paragraph-heavy instructions; help tooltips or expandable advanced details, accessible labels and error messages. Suggested order:
1. Drawing template: selected template + Change; optional accordion for template details/projection/paper.
2. Parts: Choose SLDPRT / Choose folder; selected count and concise status. Existing configuration selection under Advanced if appropriate.
3. Reference drawing: compact mode selector Standard / Match reference; when match, Auto-find / Upload PDF / Select saved source; one-line match status, change/clear; accordion for provenance/extraction details. Reuse forward history without requiring repeated upload. Optional manual upload for each batch row.
4. Advanced settings: collapsed by default; configuration, units/projection overrides, review/comparison options; do not hide critical warnings.
5. Run controls: primary Champagne Gold Run selected; Run all where applicable; concise live progress, Runtime & Cost accordion (collapsed by default, summary visible).
6. Export: at bottom of setup section; compact buttons Download SLDDRW and Download PDF, optional Download both ZIP; enable only when actual selected-run artifact exists. Clear draft/review status, require explicit acknowledgement for unapproved drawings if policy permits. Never silently label a draft as manufacturing-approved. Export actions must bind current selected part/run, not stale previous part. Show success/failure via existing notification system.

Use accessible accordion buttons with aria-expanded/controls, keyboard operation, sensible focus, no accidental run on expand. Keep state per workspace; reference panel opens when actionable issue needs resolution, not on every polling tick. Avoid nested scrollbars where possible. Rail can scroll independently on shorter screens while header/run/export remain accessible; use responsive CSS rather than hard-coded pixel offsets. Keep all controls functional and labels untruncated; compact status chips sparingly. Preserve file inputs across collapse and rerender.

## Left viewer toggle
Beside existing '3D Model (STL)' title, add segmented toggle `3D Model | Source PDF`. Show actual original reference PDF (manual or confirmed history) on left when selected; right remains generated drawing PDF. If unavailable, disable Source PDF with concise tooltip, never show generated PDF as source. Support pages, zoom, fit, pan, fullscreen using existing viewer components. Preserve view state separately per part/run/mode; reset on part change to avoid stale artifacts. Keep STL loader/material appearance and controls intact. For reference comparison, optional synchronized page/zoom when sheets correspond; do not force synchronization. Label Original / Generated clearly; display source provenance and current revision. Ensure correct loading/error/empty states and release object URLs/resources.

## Vertical workspace and batch queue
Remove blank gap between viewer row and Batch Queue. Inspect parent height, min-height, flex/grid tracks, margins, absolute positioning, overflow and any collapsed placeholder. Preferred grid: header/progress auto, content flexible minmax(0,1fr), batch queue auto immediately below content; setup rail may span content and queue if appropriate. Alternative natural flow when content exceeds viewport. Avoid forcing queue to viewport bottom with spacer/margin-top:auto if it creates dead space; if viewers expand to fill available height, allocate that space to useful viewer area, not blank background. Keep viewers aligned and equal usable height; responsive widths with min-width:0, min-height:0. Batch queue starts as compact header plus rows or collapsible summary, expands without clipping; never hide active job status. Preserve selection, cancel, retry, per-row progress and output links. At narrow widths stack viewers and rail; no horizontal page overflow. Existing Pipeline Results collapse behavior must remain functional.

## Export backend
Reuse artifact service or implement authenticated run-specific download routes by artifact ID; resolve path server-side, verify authorization/path containment and file type. Stream correct MIME (PDF application/pdf, SLDDRW application/octet-stream), attachment filename sanitized, content length and error handling. Optional ZIP generated from validated artifacts only. Preserve native SLDDRW references; offer optional packaged model dependencies if needed (do not silently replace user's original part). Reopen exported files in SolidWorks to validate portability/links where possible. No fake download buttons, no client filesystem path exposure. Handle missing/cancelled jobs, stale artifacts and batch outputs accurately.
