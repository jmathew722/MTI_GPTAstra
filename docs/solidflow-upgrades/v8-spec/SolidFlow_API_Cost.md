# SolidFlow — GPT API cost and runtime accounting

## Required implementation
Instrument every OpenAI request used by drawing extraction, OCR/vision, structured interpretation, geometry mapping assistance, drawing generation assistance, visual validation and corrections. Include retries, failed calls when usage is reported, and all pages/tiles. Local PDF parsing, rendering and SolidWorks COM execution do not themselves incur OpenAI token charges. Do not count Claude Code development-session costs as runtime GPT charges. Never expose or log the API key.

## Pricing source and calculations
Use configurable, versioned model-specific USD pricing per million tokens, verified against https://openai.com/api/pricing/ at implementation time. Store effective date, source URL, model ID, service tier and applicable input/cached input/output rates. Support model aliases explicitly; unknown rates produce unavailable cost, not zero. Account separately for any applicable non-token charges, and avoid double counting image tokens already included in input usage. Use decimal arithmetic. For each request:

uncached_input = input_tokens - cached_input_tokens
cost_usd = (uncached_input * input_rate + cached_input_tokens * cached_rate + output_tokens * output_rate) / 1,000,000 + applicable_extra_charges

Use provider usage fields for the actual endpoint (e.g. Responses API input_tokens, input_tokens_details.cached_tokens, output_tokens; adapt Chat Completions fields if used). Reasoning tokens included in output totals must not be counted twice. Distinguish provider prompt caching from local extraction cache; a local cache hit with no API call costs $0 for that stage. Preserve raw usage metadata without secrets or sensitive payloads. Deduplicate by provider response/request identity, track attempts separately, and flag missing usage as unknown rather than free. Record actual token-derived cost as calculated, not a guaranteed invoice total; reconcile with provider billing where available.

## Pre-run estimate
Inspect selected PDF pages, dimensions, image detail settings, tile count, text size, expected output schema size and planned validation/correction calls. Estimate input tokens using the configured model's supported token-counting method or documented image token rules; estimate output from historical usage for similar drawings or a clearly labeled conservative fallback. Do not treat OCR characters or image pixels as tokens directly. Estimate each stage separately, with low/expected/high scenarios reflecting retries and correction caps. Include cached extraction savings only when reuse is confirmed. Display configured model, rate date, expected token totals, expected USD and range. Show unavailable when necessary. Recompute on source/model/settings changes. Budget cap should prevent starting a new call when projected spend exceeds remaining budget; disclose that in-flight requests can exceed estimates.

## Illustrative calculation (not current model pricing)
Assume input $2.50/M, cached input $0.25/M, output $10/M, no extra fees. Extraction 20,000 uncached input + 4,000 output = $0.0900. Drawing interpretation 8,000 uncached input + 2,000 output = $0.0400. Validation/correction 12,000 uncached input + 2,000 output = $0.0500. Total $0.1800. These are hypothetical rates and usage, not a quote for the user's model. Actual values must come from configured pricing and observed usage.

## Runtime and UI
Show in Workspace Run Pipeline: estimated duration and range, estimated cost and range, elapsed time, cumulative calculated actual cost, current stage, completed/total pages or parts, and remaining estimate when meaningful. Use measured historical stage durations by page count, complexity, cache and model; fallback estimates must be labeled. Measure wall-clock duration with monotonic clocks; parallel stage durations must not be summed as elapsed wall time. Track queue time separately. Persist stage breakdown (extraction, drawing assistance, local generation, validation, correction), model, tokens, cached tokens, calls, cost, elapsed, rate version and uncertainty. For batch, aggregate all parts and show per-part breakdown. On completion show actual elapsed and token-derived cost versus estimate; on cancellation/failure retain incurred costs. Use sufficient precision for sub-cent calls and never display unknown as $0.00. Add tests for cached input, multiple models, retries, duplicate events, missing usage, local cache, cancellation, rate changes, budget caps and concurrent jobs. Do not claim actual cost without usage evidence.
