# Workspace collapsibles report (2026-11-26, v6)

Scope: 2D->3D workspace only. Material Selection accordion, Runtime & cost accordion, Pipeline Results drawer behaviour. The 3D->2D page was not changed (spec 31 and new test 109 confirm it still loads without script errors).

## What was verified first (drawer, before any change)
Probe on an isolated server at 1366x768 and 1920x1080 (`before-stored-open-*.png`): the expanded drawer was 320 px high, its bottom was flush with the workspace bottom (drawer bottom 1070 of 1080, page padding 10), `#main` did not scroll (the v5 dead-scroll fix holds). So the earlier fix was intact. What the user can still see as "a shallow strip" is the fixed 320 px default height: on a 1080 px screen the viewers keep about 590 px and the drawer is a 320 px strip. Also, the persisted `open: true` made the drawer reopen on every load, and a failed or warning run opened it automatically. All three are changed (below).

## Changes
- A. `index.html`: `#mat-lib` is now `.msec`: header button `#mat-acc-btn` (label, status `#mat-acc-sum`, chevron), warning line `#mat-acc-warn` (visible while collapsed), body `#mat-acc-body` holding every existing control (Browse Folder, library line and errors, View catalog, Refresh, Use demo catalog, path entry, "Material of this part" card). All old element ids are kept.
- B. `#run-estimate` sits inside `#rt-acc` ("Runtime & cost"), collapsed by default. Rows: Status, Estimated time; "OpenAI execution cost (model calls only)": Estimated cost, and while running Elapsed, Time left, Cost so far, Part n of m; "Material cost (separate, not OpenAI)": selected part. The header shows live status and short elapsed time (`Running · 1m 12s`). Unknown shows N/A, remaining time is clamped (never negative), and the one-line live text is hidden while the rows show (no duplicate). An estimate failure appears in the collapsed header ("Estimate unavailable"). Cancel buttons are outside the accordion.
- C. `core/persist.js`: the drawer open flag is never restored. `ui/drawer.js`: removed the auto-open on failed/warning completion. `logic/drawersize.js`: `autoHeight(max)` = available maximum minus the viewer share (300 px, or 40% of the space on small windows), used only when the user never resized for that viewport class; Fit, Maximize/Restore, drag and keyboard resize are unchanged. `ui/sidebar.js`: New Project closes the drawer and collapses both accordions.
- New: `logic/collapsibles.js` (pure summaries), `ui/accordions.js`, CSS `.msec*` / `.rt-*` in `workspace.css`; `features/materials.js` (`libError()`, emit on failure); `features/estimate.js` (row rendering, material row).
- Fixed trivially: created the missing `tests/fixtures/part_full.log` and `part_cancelled.log` (they were gitignored by `*.log`; committed with `-f`). The `logparse` test now passes.

## Unverified / limitations
- Real browser zoom (Ctrl +/-) was not driven; zoom is emulated through device metrics, which is what layout sees.
- At 150% zoom on 720/768-high screens (CSS height under 540 px) header + tracker leave less than the drawer's 160 px minimum, so opening the drawer hides the viewers (same as Maximize; header, Fit/Maximize and close stay reachable). The spec relaxes the viewer-height check only there.
- "Fills the available space" is implemented as: bottom flush with the workspace bottom (already true before), and a taller default (about 580 px of 880 at 1920x1080); at 1366x768 the drawer is about 340 px so the viewers stay usable. If the drawer should take everything by default, raise the drawer share in `autoHeight` or default to Maximize. This is a product decision I did not make.
- Live runs were simulated by dispatching store events; no real run and no real cancel request. "Cost so far" was seen only as N/A (no telemetry in a simulated run).
- The app has no separate footer or status bar; "workspace bottom" is the workspace content box bottom (page bottom minus padding).
- The spec teardown deletes data it did not create: the seeded `V5Audit` session part had to be re-seeded between runs. `tests/e2e/run_v6_all.sh` seeds and runs the suite on a throwaway server; it was not itself executed end to end (the equivalent manual commands were).
