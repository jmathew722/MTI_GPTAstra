### Comparison (3D -> 2D)
- **Side by side with synchronised zoom, pan and page.** Source PDF (left, `3D Model | Source PDF`) and generated PDF (right). Sync is **on by default** and effective only when both sheets are loaded and have the same page count; otherwise the toggle is disabled with the reason (`2 source vs 1 generated`). Page, zoom and scroll position (as a fraction of the scrollable range, so sheets of different canvas size stay aligned) follow in both directions. Pan echoes are recognised by position, not by a time window, so a real scroll right after a synced one is never swallowed.
- **Overlay and Difference** (`Side by side | Overlay | Difference` above the generated sheet). When the backend lists an overlay / difference image for the sheet (`replication.images` or `files.comparison_images`, matched by name and page) that image is laid exactly over the generated sheet and labelled "produced by the backend". When it does not, the overlay / difference is **computed in the browser** from the two rendered canvases, labelled "computed in your browser ... not a backend result; pixels are not a measurement of tolerance", with a colour legend (blue = only in the source = missing, red = only in the generated drawing = extra, grey = both) and the differing pixel counts. Disabled with the reason when there is no source PDF (Standard, blocked, ...).
- **Status chip**: `Verified | Needs Review | Blocked | Failed | Pending` from `replication.status`; a v7-only part (no replication block) is `Draft: checks passed (not verified against a source)`, never "Verified". No label says "approved".
- **Comparison tab** (second tab): status and reason, issue list (grouped Missing / Extra / Mismatched / Other with counts, severity ordered, keyboard operable: arrows move, Enter shows the evidence), facts (sheet and per-view scales "Sheet 1:2 source / 1:2 generated (title block 1:2)", "differs" flag, extraction reuse hit / supplemented / fresh, correction count "1 of 3 correction pass (stopped: iteration cap)", annotation counts, completeness, extra pages from `replication.pages[]`, SLDDRW availability) and the evidence panel.
- **Click-to-focus on evidence.** A missing / mismatched item is shown on the **source** (switches the left viewer to Source PDF, goes to the issue's sheet), an extra item on the **generated** sheet. The item is located by `issue.evidence.bbox` when the backend gives page fractions, otherwise by **searching the page's own text layer** for `issue.text`; the box is highlighted and scrolled into view and a crop of the region is shown beside the list. If the text cannot be found (a scanned drawing, or text in neither PDF) the page is shown and the panel says so; nothing is highlighted and no crop is faked.
- Per part / per run state (mode, filter, evidence), loading / error (Retry) / empty states, no object URLs created (asserted), `aria-pressed` toggles, `aria-live` evidence note, visible focus.

### Export
`GET /api/reverse/jobs/{job}/parts/{part}/export/report` (and `kind: report` in the export info). Same containment, MIME (`application/json`), 409 (stale `expect`, canceled, not finished, acknowledgement missing) and 404 rules as SLDDRW / PDF; the file is the part's `replication/report.json` when it exists, otherwise `qa.json`. The ZIP is unchanged (SLDDRW + PDF only). The status is computed on the server from `replication` and `verification`: **Verified against the source drawing (not an engineering approval)** (green, no acknowledgement) only when the backend says `verified` and nothing else is open; `needs_review`, `blocked`, `pending` need the acknowledgement, `failed` is red. A verified replication never relaxes a v7 verification that did not pass.

### Cost and runtime
- **Before the run** (`POST /api/reverse/estimate`, body `{count, reference, stage_id?, keys?}`): staged parts (Match mode) go to `ReverseService.estimate_run(paths, reference)`; the browser only names keys, paths never leave the server. Without staged parts, or when `estimate_run` is missing or fails, the answer is built from history only: a duration range (no invented "expected"), cost a **real zero only for Standard** (that path makes no model call) and **unavailable** (`null`) for Match. Shown: time range and expected, cost low / expected / high with model and rate date, tokens, budget (cap, remaining, "a request already in flight can exceed its estimate", would-block warning), confirmed extraction reuse, fallback labels, stage table, assumptions, "Local CAD processing time carries no token cost". One summary line sits under Run selected / Run all. Recomputed when the selection, mode, per-part source choices, template or profile change; never starts a run.
- **During / after** (job view `usage`, `timing`, `estimate`, `estimate_vs_actual`): status, parts done / total, current stage, elapsed (server monotonic value plus the browser's own monotonic clock between polls, ticking once a second; never backward between polls), queue wait kept separate, remaining only when the backend gives one (labelled "rough" for a fallback), cumulative cost with four decimals under $10 ("$0.0043", "calculated from token usage, not an invoice"), tokens in / cached / out, calls, local cache hits, retries, stage breakdown (extraction, drawing assistance, validation, correction with tokens, cached, calls, cost; local CAD time per stage labelled "no token cost"), actual vs estimate with "within / outside the estimated range", batch aggregate plus per-part rows, failed and canceled parts keep their incurred cost with a note, header chip `$0.0212 API usage (calculated)`.
- **Wording rules** (unit-tested): `null` cost is "unavailable" and never `$0.00`; `partial` is "$0.0100 + unpriced calls"; `unpriced` is "unavailable"; a local cache hit is "$0.00" with no model call and a saving is stated only when `cache_hits > 0` and `historical_usd` is known ("saves about $0.2000"), otherwise "the original cost is not recorded"; no usage fields is "Usage was not recorded for this run".
- **2D -> 3D workspace** (Runtime & cost accordion): the existing estimate source is kept; `/api/estimate` now also returns the median as `expected` (real history, absent when there is none) and the model and rate date of the latest ledger row (null when unknown); `/last-run` returns a V8-shaped `usage` built from the ledger. The UI shows "expected" next to the range, "Model gpt-6-astra - rates of ...", the last run's calls by stage (tokens, cached, calls, cost), retries, actual vs estimate range, and states that SolidWorks build time carries no token cost.

### Harness fix found on the way (not a product bug)
`run_v5/v6/v7_all.sh` stopped their server with `taskkill //PID $(cat pid)`, but `$!` is an MSYS pid, so the Windows python server kept running; a later run on the same port silently tested that stale server and its old data. That produced misleading failures (including the two "known" base failures seen in earlier reports, which pass on a fresh server) during this work. The scripts now refuse to start when the port is in use and stop the server by port (`netstat` + `taskkill`).

## 4. Limitations and not tested
- **Backend fields were not produced by a real replication run.** Browser specs inject `replication`, `usage`, `timing`, `estimate` in the V8_CONTRACT shapes into `GET /jobs/<id>`; the real backend currently returns `replication: null` for fixture jobs and `usage.calls: 0`. A real Match run (paid, SOLIDWORKS) was not done.
- **The "Verified" export label** is covered by pytest (server) and unit tests, not by a browser test, because the browser seed cannot make the real backend report `replication.status == verified`.
- **Issue evidence** has no bbox in the V8 contract; evidence is located through the page text layer. A scanned PDF has no text layer, so the page is shown without a highlight (stated in the UI). If the backend later adds `evidence.bbox` (page fractions 0..1) it is used automatically; absolute units are ignored rather than guessed.
- **Standard mode estimates are history-only**: the browser has not uploaded the parts, so `estimate_run` (which needs server paths) cannot be called; cost is the stated zero for Standard. Match mode uses `estimate_run` once the parts are staged. Staged copies are the v7 mechanism (swept after 6 hours).
- **Pages completed / total** is shown as parts completed / total; the contract has no per-page progress.
- **In-browser overlay / difference** is a pixel comparison of two rendered sheets (fit inside each other if their proportions differ); it is a visual aid, not a tolerance measurement, and is labelled so. It is recomputed when the sheet or the source page re-renders.
- Browser zoom is emulated with CDP device metrics. At 1280x720 with the sidebar expanded the rail is short; the rail scrolls itself, the Export block stays pinned (known from v7).
- The 2D -> 3D `usage` per stage uses the ledger roles as stage names (`extractor`, `planner`, ...), not the 3D -> 2D names; `rate_version` is the pricing file's `as_of` for the latest row's model and is null when it cannot be told.
